## 0. 开工前检查

在本地终端执行：

```bash
# 项目能构建吗
cd backend && go version && go build ./... && cd ..
cd frontend && node -v && pnpm -v && cd ..
```

三件事必须先确认，否则后面全白搭：

| 检查项 | 怎么查 | 不满足怎么办 |
|---|---|---|
| 服务器是**包年包月** | ECS 控制台 → 实例 → 付费方式 | 按量付费不能备案，需转包年包月 |
| 域名**实名满 3 个工作日** | 阿里云域名控制台 → 实名认证时间 | 等；提前提交会被退回 |
| 域名后缀可备案 | `.com` `.cn` `.xyz` `.top` 等均可 | 冷门后缀查工信部批复名单 |

## 1. 本地构建

Mac / Linux 上产出**给 Linux 服务器用**的二进制，必须交叉编译。

```bash
cd /path/to/blog-learn

# 如果本地 Go 版本低于 go.mod 要求，会触发 toolchain 下载
# 国内网络必须同时设这两个，否则 sumdb 校验超时
export GOPROXY=https://goproxy.cn,direct
export GOSUMDB=sum.golang.org

# 一键构建（脚本已内置交叉编译）
./deploy/build.sh
```

脚本内部等价于：

```bash
# 后端
cd backend
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  go build -trimpath -ldflags "-s -w" -o bin/blog-server ./cmd/server

# 前端
cd ../frontend
pnpm install --frozen-lockfile && pnpm build
```

**验证产物**：

```bash
file backend/bin/blog-server
# 期望：ELF 64-bit LSB executable, x86-64, statically linked

du -sh backend/bin/blog-server frontend/dist
# 期望：约 22M 和 1.0M
```

> ⚠️ 两个关键点：
> - `GOOS=linux` —— 不加就产出 darwin 二进制，服务器报 `cannot execute binary file`
> - `CGO_ENABLED=0` —— 加静态链接，避免服务器 glibc 版本不匹配

## 2. 服务器初始化

### 2.1 登录服务器

```bash
# 首次：把公钥装上去（会提示输入 root 密码）
ssh-copy-id -i ~/.ssh/id_ed25519.pub root@你的服务器IP

# 验证免密
ssh root@你的服务器IP 'echo ok'
```

### 2.2 建用户和目录

```bash
ssh root@你的服务器IP

# 建专用低权限用户（不要用 root 跑服务）
id blog >/dev/null 2>&1 || useradd -r -m -s /bin/bash blog

# 建目录
mkdir -p /opt/blog/backend/bin /opt/blog/backend/uploads /var/www/blog /backup
chown -R blog:blog /opt/blog /var/www/blog
```

### 2.3 装依赖

**Alibaba Cloud Linux / CentOS / RHEL：**

```bash
dnf install -y nginx mysql-server curl rsync
# 老系统用 yum install -y ...
```

**Ubuntu / Debian：**

```bash
apt update
apt install -y nginx mysql-server curl rsync
```

> ⚠️ **必须装 MySQL 8，不能装 MariaDB。** 迁移脚本用了 `utf8mb4_0900_ai_ci`，MariaDB 不支持这个 collation，建表会报错。
>
> 查包名：`dnf list available | grep -E "^mysql"`

### 2.4 启动服务

```bash
# RHEL 系服务名是 mysqld，Ubuntu 是 mysql
systemctl enable --now mysqld    # Ubuntu: mysql
systemctl enable --now nginx

systemctl is-active mysqld nginx
```

## 3. 上传产物

在**本地**终端执行（不是服务器上）：

```bash
cd /path/to/blog-learn
T=root@你的服务器IP

rsync -az backend/bin/blog-server  $T:/opt/blog/backend/bin/
rsync -az --delete frontend/dist/  $T:/var/www/blog/dist/
rsync -az backend/migrations/      $T:/opt/blog/backend/migrations/
rsync -az backend/.env.prod        $T:/opt/blog/backend/.env.prod
rsync -az deploy/                  $T:/opt/blog/deploy/
```

> `--delete` 会删除服务器上 dist 里多出来的旧文件，保证发版干净。

**修正属主**（rsync 会保留本机的 uid/gid，必须改）：

```bash
ssh $T 'chown -R blog:blog /opt/blog/backend && chmod 600 /opt/blog/backend/.env.prod'
```

### 生产配置 `.env.prod` 怎么来

三种方式任选：

```bash
# 方式 A：脚本生成（推荐，自动填好 prod 口径 + 随机 JWT）
./deploy/gen-env.sh --out backend/.env.prod --db-password '你的数据库密码'

# 方式 B：从模板手改
cp backend/.env.example backend/.env.prod
vim backend/.env.prod

# 方式 C：在服务器上生成
ssh $T 'bash /opt/blog/deploy/gen-env.sh --out /opt/blog/backend/.env.prod'
```

**生产必须改的项**：

| 变量 | 值 | 不改会怎样 |
|---|---|---|
| `APP_ENV` | `prod` | `/debug/*` 路由和 SQL 打印暴露在公网 |
| `DB_PASSWORD` | 强密码 | — |
| `JWT_SECRET` | `openssl rand -hex 32` 新生成 | 本地密钥泄露过就能伪造登录 |
| `TRUSTED_PROXIES` | `127.0.0.1` | 评论 IP 全是 127.0.0.1，限流误伤所有人 |
| `UPLOAD_DIR` | `/opt/blog/backend/uploads` | 相对路径依赖工作目录，图片可能丢 |
| `COMMENT_RATE_LIMIT` | 例如 `3` | 评论无防刷 |

## 4. 建库与迁移

### 4.1 建库（在服务器上，以 root 执行）

```bash
ssh root@你的服务器IP

# RHEL 系源码包安装的 MySQL，root 通常免密
mysql -uroot <<'SQL'
CREATE DATABASE IF NOT EXISTS blog DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'blog'@'localhost' IDENTIFIED BY '你的数据库密码';
GRANT ALL PRIVILEGES ON blog.* TO 'blog'@'localhost';
FLUSH PRIVILEGES;
SQL
```

> 如果报 `Access denied`，说明 root 有密码。查临时密码：
> `grep 'temporary password' /var/log/mysqld.log`

### 4.2 执行迁移

```bash
cd /opt/blog/backend
export MYSQL_PWD='你的数据库密码'

for f in migrations/00*.sql; do
  echo "==> $f"
  mysql -ublog --default-character-set=utf8mb4 blog < "$f"
done
```

> ⚠️ **`--default-character-set=utf8mb4` 绝对不能省。**
> 服务器上 `LANG` 通常是空的，mysql 客户端默认用 latin1，UTF-8 的种子文件会被**双重编码**，页面显示成 `Go ä»Žé›¶å¼€å§‹`。
> 判断方法：`SELECT HEX(SUBSTRING(title,4,1))`，正确是 `E4BB8E`，双重编码是 `C3A4`。

**验证**：

```bash
mysql -ublog --default-character-set=utf8mb4 blog -e "
  SELECT HEX(SUBSTRING(title,4,1)) AS byte, CHAR_LENGTH(title) AS chars
  FROM articles WHERE id=1;"
# 期望：E4BB8E，chars≈19
```

## 5. 启动后端

### 5.1 装 systemd 单元

```bash
cp /opt/blog/deploy/blog-server.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable blog-server
systemctl start blog-server
```

单元文件的关键内容（`deploy/blog-server.service`）：

```ini
[Service]
User=blog
WorkingDirectory=/opt/blog/backend
Environment=ENV_FILE=/opt/blog/backend/.env.prod
ExecStart=/opt/blog/backend/bin/blog-server
Restart=always
ProtectSystem=strict
ReadWritePaths=/opt/blog/backend/uploads
```

### 5.2 验证

```bash
systemctl is-active blog-server          # 期望 active
ps -eo user,args | grep "[b]log-server"  # 期望属主是 blog
ss -lntp | grep 8090                     # 期望监听
curl -s http://127.0.0.1:8090/api/v1/ping
# 期望 {"code":0,"message":"ok","data":{"pong":true}}
```

失败就看日志：

```bash
journalctl -u blog-server -n 50 --no-pager
```

## 6. 配置 Nginx

### 6.1 安装站点配置

```bash
# 备案期间先用 8080，避免 80 被抽查
sed "s/listen 80;/listen 8080;/" \
  /opt/blog/deploy/nginx-youzhichong.xyz.conf > /etc/nginx/conf.d/blog.conf

# 删掉默认站点，避免抢 80
rm -f /etc/nginx/conf.d/default.conf
rm -f /etc/nginx/sites-enabled/default

nginx -t
systemctl reload nginx
```

### 6.2 配置要点

```nginx
server {
    listen 8080;
    server_name youzhichong.xyz www.youzhichong.xyz;
    root /var/www/blog/dist;

    # SPA 必须回退，否则刷新 /article/1 会 404
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 反代后端，proxy_pass 结尾不带 / 才保留 /api 前缀
    location /api/ {
        proxy_pass http://127.0.0.1:8090;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location /uploads/ {
        proxy_pass http://127.0.0.1:8090;
    }

    client_max_body_size 8m;
}
```

### 6.3 验证

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/          # 200
curl -s http://127.0.0.1:8080/api/v1/ping                                # ok
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/article/1 # 200（SPA 回退）
```

## 7. 放行安全组

**控制台操作**：ECS → 实例 → 安全组 → 配置规则 → 入方向 → 手动添加

| 字段 | 值 |
|---|---|
| 授权策略 | 允许 |
| 优先级 | 1 |
| 协议类型 | 自定义 TCP |
| 端口范围 | `8080/8080` |
| 授权对象 | `你的公网IP/32`（自测）或 `0.0.0.0/0`（所有人） |

> 端口范围必须写成 `8080/8080`，只写 `8080` 会报错。
> 查自己公网 IP：`curl -s https://myip.ipip.net`

**命令行操作**（可选，需要 AccessKey）：

```bash
aliyun configure set --mode AK \
  --access-key-id '...' --access-key-secret '...' \
  --region cn-shenzhen --language zh

aliyun ecs AuthorizeSecurityGroup \
  --RegionId cn-shenzhen \
  --SecurityGroupId sg-xxxxxxxx \
  --IpProtocol tcp \
  --PortRange 8080/8080 \
  --SourceCidrIp 0.0.0.0/0 \
  --Description "blog-8080"

# 用完删掉凭据
rm -f ~/.aliyun/config.json
```

> ⚠️ 不要长期在服务器上存 AccessKey。要自动化就用**实例 RAM 角色**。

## 9. 域名与备案

### 9.1 域名解析

阿里云云解析 → 添加两条 A 记录：

| 主机记录 | 类型 | 值 |
|---|---|---|
| `@` | A | 服务器公网 IP |
| `www` | A | 服务器公网 IP |

**验证**（不要只看控制台，要看实际解析）：

```bash
curl -s "https://dns.alidns.com/resolve?name=yourdomain.xyz&type=A"
# Status=0 且 Answer 有 IP 才算生效；Status=3 是 NXDOMAIN
```

> 如果控制台显示「实名认证成功」但解析仍是 NXDOMAIN，查 RDAP：
> `curl -s "https://rdap.centralnic.com/xyz/domain/yourdomain.xyz"`
> `status` 里只要有 `client hold`，就说明注册局还没解除，改任何解析记录都不会生效，必须提工单。

### 9.2 ICP 备案

**前提**：ECS 包年包月 + 域名实名满 3 个工作日。

入口：控制台搜索「备案」→ <https://beian.aliyun.com>

**填写要点**：

| 字段 | 怎么填 |
|---|---|
| 网站名称 | **3 个汉字以上**，且**不能含「博客」** |
| 网站服务内容 | 个人备案只能选「其他」 |
| 备注 | 必须写，说明个人非经营用途 |

**个人备案网站名称禁用词**：博客、论坛、在线、社区、交流、分享、个人空间、爱好者、导航、工作室、平台、热线、社团、网络、网站、网址、主页、资讯、作品展示。

可用示例：`智虫技术手记`、`编程学习手记`、`技术成长记录`。

**备注示例**：

> 本网站为个人学习使用，主要记录编程技术学习过程中的笔记与心得，不涉及任何商业经营活动。

**时间**：阿里云初审 1~2 工作日，管局 1~20 工作日。

**备案期间**：网站必须关闭。把 80 的安全组改成只允许自己 IP，或停止域名解析。

### 9.3 备案通过后

```bash
# 1. nginx 切到 80
sed -i 's/listen 8080;/listen 80;/' /etc/nginx/conf.d/blog.conf
nginx -t && systemctl reload nginx

# 2. 签证书（见下一节）
```

还要做两件事：

- 网站底部加 **ICP 备案号**，链接到 `https://beian.miit.gov.cn`
- **30 日内**完成公安联网备案：<https://beian.mps.gov.cn>

## 10. 上 HTTPS

```bash
# Ubuntu
apt install -y certbot python3-certbot-nginx
certbot --nginx -d yourdomain.xyz -d www.yourdomain.xyz

# RHEL / Alibaba Cloud Linux（可能需要 epel）
dnf install -y epel-release
dnf install -y certbot python3-certbot-nginx
certbot --nginx -d yourdomain.xyz -d www.yourdomain.xyz
```

如果 certbot 装不上，用 acme.sh（不依赖包管理器）：

```bash
curl https://get.acme.sh | sh
~/.acme.sh/acme.sh --issue -d yourdomain.xyz -w /var/www/blog/dist
~/.acme.sh/acme.sh --install-cert -d yourdomain.xyz \
  --key-file /etc/nginx/ssl/yourdomain.key \
  --fullchain-file /etc/nginx/ssl/yourdomain.crt \
  --reloadcmd "systemctl reload nginx"
```

**验证续期**：

```bash
certbot renew --dry-run
```

最后安全组放行 80 和 443。

## 11. 排错手册

| 现象 | 原因 | 处理 |
|---|---|---|
| `cannot execute binary file` | 传了 macOS 二进制 | 重新交叉编译（`GOOS=linux GOARCH=amd64`） |
| `GLIBC_2.xx not found` | 动态链接 + 服务器 glibc 旧 | 加 `CGO_ENABLED=0` 重编 |
| 502 Bad Gateway | 后端没起 / 端口不对 | `systemctl status blog-server`、`journalctl -u blog-server -n 50` |
| 刷新详情页 404 | nginx 缺 SPA 回退 | 加 `try_files $uri $uri/ /index.html` |
| 中文乱码 | 导入时客户端 latin1 | 重导并加 `--default-character-set=utf8mb4` |
| 图片 413 | 上传超过 `client_max_body_size` | nginx 调到 ≥ `UPLOAD_MAX_MB` |
| 评论 IP 全是 127.0.0.1 | 没配 `TRUSTED_PROXIES` | `.env.prod` 设 `127.0.0.1` 后重启 |
| 域名 NXDOMAIN，但面板正常 | 注册局 `clientHold` | 查 RDAP，提工单 |
| 域名能解析但打不开 | 安全组没放行 | 检查 80/443 入方向规则 |
| 8080 外网不通、服务器内正常 | 安全组 | 同上 |
| 服务启动即退出 | `.env.prod` 缺失或字段错 | `journalctl` 看「缺少 DB_PASSWORD」这类报错 |
| 发版后页面还是旧的 | `index.html` 被缓存 | 对 `/index.html` 设 `no-cache` |

## 附：日常运维命令

```bash
# 服务
systemctl status blog-server

journalctl -u blog-server -f
```
