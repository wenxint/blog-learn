## 我踩过的坑（最值得记住的 8 个）

1. **中间件校验失败没 `Abort()`** → 业务 handler 继续执行，等于鉴权被绕过。文章 05。
2. **网络抖动清掉 token** → 后端一重启全员掉线。只有明确 401 才能清登录态。文章 05。
3. **Nginx 不配 `TRUSTED_PROXIES`** → 所有评论 IP 都是 127.0.0.1，限流把全站当一个人。文章 06。
4. **固定窗口限流的边界** → 整点前后各打满一次，2 秒内放行双倍。文章 06。
5. **`v-html` 直接渲染 Markdown** → 一个 `onerror` 就能偷 token；必须 DOMPurify。文章 08。
6. **marked v5 删了 `setOptions({highlight})`** → 代码有颜色是假象，回调根本没跑。文章 08。
7. **esbuild 把媒体查询改写成 Level 4 语法** → 旧 Safari 整个移动端样式失效；需 `cssTarget` 降级。文章 09。
8. **域名 `clientHold` 时先重启了服务** → 真正问题在域名状态，不在应用；排错要按层来。文章 10。

更多按时间倒序的记录在 [notes/踩坑记录.md](notes/踩坑记录.md)。

## 自我评估

### 现在能独立做的

- 从零搭一个 Go + Vue3 的前后端分离项目，包含认证、分页、评论、上传
- 设计 6～10 张表的关系与索引，写出能走索引的查询
- 把一个 Go 服务交叉编译、用 systemd 托管、用 Nginx 反代上线
- 定位「页面不对 / 接口不对 / 数据不对」分别该看哪一层
- 给一个功能配一张能讲清结构的图，并把结论写成图注

### 还需要查资料才能做的

- 多实例部署下的会话、限流、缓存一致性
- 复杂 SQL 调优和百万级数据下的索引设计
- 前端组件测试、E2E 测试体系
- 证书自动续期、监控告警、日志聚合

### 还没做过的

- 多人协作（Code Review、分支策略、冲突处理）
- CI/CD（GitHub Actions 或 GitLab CI）
- 真实高并发压测与容量评估
- iPhone Safari / Android WebView 真机验证

## 怎么验证这份档案不是自说自话

```bash
# 1. 后端单测与静态检查
cd backend && go vet ./... && go test ./... -count=1

# 2. 接口与诊断
curl -s http://127.0.0.1:8090/api/v1/ping
curl -s http://127.0.0.1:8090/api/v1/debug/db | python3 -m json.tool
curl -s http://127.0.0.1:8090/api/v1/debug/models | python3 -m json.tool

# 3. 限流（第 4 条应为 429）
for i in 1 2 3 4; do curl -s -o /dev/null -w "%{http_code} " -X POST \
  http://127.0.0.1:8090/api/v1/articles/1/comments \
  -H "Content-Type: application/json" \
  -d "{\"nickname\":\"t\",\"content\":\"x$i\"}"; done; echo

# 4. 未登录访问后台（应为 401）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8090/api/v1/admin/articles

# 5. 索引
mysql -ublog -p blog -e "EXPLAIN SELECT * FROM articles WHERE status=1 ORDER BY published_at DESC\G"

# 6. 前端
cd frontend && pnpm build
```

如果上面这些命令的实际输出和本文、和文章里写的不一致，以现场输出为准——文档可能过期，代码不会说谎。
