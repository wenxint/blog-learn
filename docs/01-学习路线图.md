## 各课实际内容与验收

### ✅ 第 1 课：环境 + 第一个 Go 服务

**做了什么**：用标准库 `net/http` 起一个 `:8090` 服务，两个路由 `/ping`、`/hello`，手写 JSON 输出。

**关键认知**
- `func(w http.ResponseWriter, r *http.Request)` 就是 HTTP 的「读请求 / 写响应」两件事
- `w.Header()` 必须在 `w.WriteHeader()` 之前设置
- **HTTP 状态码和业务 code 是两个维度**（这一课埋下了 `response` 包的种子）

**为什么代码不见了**：第 3 课换成了 Gin，`main.go` 被整体替换。原始代码在 `git show 072bbcd:backend/cmd/server/main.go`。

---

### ✅ 第 2 课：MySQL + SQL 建表

**做了什么**：装 MySQL 8.4、建 `blog` 库和专用账号、手写 4 张表的 DDL 与种子数据。

**关键认知**
- 主键用 `BIGINT UNSIGNED AUTO_INCREMENT`，不要用 `INT`
- 布尔用 `TINYINT` 0/1；金额用 `DECIMAL` 不用 `FLOAT`
- 字符集必须 `utf8mb4`（`utf8` 其实是 `utf8mb3`，存不了 emoji）
- **联合索引顺序决定能否走索引**：`(status, published_at)` 能服务 `WHERE status=? ORDER BY published_at`，反过来不行 → 实验结果见 `notes/踩坑记录.md`

**验收命令**
```bash
mysql -ublog -p blog -e "SHOW CREATE TABLE articles\G"
mysql -ublog -p blog -e "EXPLAIN SELECT * FROM articles WHERE status=1 ORDER BY published_at DESC\G"
# key=idx_status_published、Extra 无 Using filesort 才算过
```

### ✅ 第 3 课：Gin + 统一响应 + 中间件

**做了什么**：7 个文件，4 层中间件（RequestID → Logger → Recovery → CORS）再进 handler。

**关键认知**
- 中间件是**洋葱模型**：`c.Next()` 之后的代码等内层跑完才执行，所以日志能拿到最终状态码
- `RequestID` 必须在最外层，Logger/Recovery 才能读到
- 中间件失败必须 `c.Abort()`，否则会继续进入业务 handler（**权限绕过漏洞**）
- 未知路由要 `r.NoRoute()` 返回统一 JSON，否则前端拦截器解析崩

**验收**
```bash
curl -i http://127.0.0.1:8090/api/v1/nope     # 404 + JSON 而非 text/plain
curl http://127.0.0.1:8090/api/v1/debug/panic # 500 + JSON，之后服务仍存活
```

### ✅ 第 4 课：配置 + 连接池

**做了什么**：`.env` 加载、必填校验、DSN 拼装、连接池三参数、`Ping()`、优雅关闭、配置层单测。

**关键认知**
- 配置错误必须在**启动时**炸掉，而不是第一次请求才发现
- `gorm.Open` 是惰性的，**必须 `Ping()`** 才知道真连上了
- 连接池：`MaxOpenConns` / `MaxIdleConns` / `ConnMaxLifetime` 各防什么问题（见代码注释）
- DSN 里有明文密码 → 日志用 `SafeDSN()` 脱敏
- 优雅关闭顺序：先 `srv.Shutdown()` 再进行中的请求排空，**最后**才关数据库

**验收**
```bash
DB_PASSWORD=wrong go run ./cmd/server; echo $?   # 退出码非 0，错误信息明确
kill -TERM <pid>                                  # 日志出现「进行中的请求已排空」
```

### ✅ 第 5 课：GORM 模型 + 真实查询

**做了什么**：6 个模型，与 6 张表逐字段对齐；`/debug/models` 接口自动比对差异。

**关键认知**
- 命名自动推导：`Article` → `articles`，`ViewCount` → `view_count`
- `password_hash` 必须 `json:"-"`（泄漏 = 重大事故）
- 允许 NULL 的时间字段必须用 `*time.Time`
- 软删除用 `gorm.DeletedAt`，查询自动加 `deleted_at IS NULL`
- **Preload 解决 N+1**：1 条主查询 + 3 条预加载 = 永远 4 条，而不是 1+N
- `*gorm.DB` 有状态，复用会串条件 → 用函数每次返回干净对象

**验收**
```bash
curl -s http://127.0.0.1:8090/api/v1/debug/models | python3 -m json.tool
# 所有模型的 missing_in_db / extra_in_db 都应为空
```

### ✅ 第 6 课：CRUD + 事务

**做了什么**：文章增删改查，含标签全量替换、状态流转、软删除。

**关键认知**
- **事务三要素**：`db.Transaction(func(tx))`、拿到 `tx` 一路往下传、返回 error 自动 ROLLBACK
- 「文章 + 标签关联」必须同事务，否则会写出「有文章没标签」的脏数据
- 状态流转：草稿→发布补 `published_at`，发布→草稿清空
- 阅读数自增用 `gorm.Expr("view_count + 1")`，**不能先读再写**（并发丢计数）
- 软删除：`Delete()` 变成 `UPDATE deleted_at`，数据还在

**验收**
```bash
curl http://127.0.0.1:8090/api/v1/debug/tx-rollback
# rolled_back 必须为 true
```

### ✅ 第 7 课：分层重构

**做了什么**：把 SQL 从 handler 挪进 repository，业务规则挪进 service。

**关键认知**
- 依赖单向：`handler → service → repository → gorm`
- 依赖注入：`NewArticleHandler(svc)`，装配集中在 `router.New()`
- service 返回哨兵错误（`ErrNotFound` / `ErrInvalidInput` / `ErrConflict` / `ErrUnauthorized`），handler 翻译成状态码
- **500 错误对外只给笼统消息**，细节写日志（否则表名/字段名就是情报）

### ✅ 第 8 课：bcrypt + 注册

**关键认知**（`pkg/hash/password.go`）
- 为什么不能存明文：拖库、内部泄漏、误连生产
- 为什么不用 MD5/SHA：它们快 = 好爆破；bcrypt 故意慢（cost=10 约 60ms/次）
- 随机盐：同一密码两次哈希不同，但都能验通过 → 彩虹表失效
- **bcrypt 只取前 72 字节**，必须显式拦截超长密码
- 哈希不可逆 → 「忘记密码」只能重置

**测试**：`internal/pkg/hash/password_test.go` 6 个用例

---

### ✅ 第 9 课：登录 + JWT

**关键认知**（`pkg/jwt/jwt.go`）
- JWT = `header.payload.signature`，**payload 只是 Base64，不是加密** → 不能放敏感信息
- 防篡改靠签名：改 payload 则验签失败
- 密钥泄漏 = 任何人可伪造任意身份 → 密钥只在 `.env`
- **必须限定算法**（`WithValidMethods`），否则 alg=none 攻击
- 登录失败统一提示「用户名或密码错误」，防止用户名枚举

**测试**：`internal/pkg/jwt/jwt_test.go` 6 个攻击场景用例

---

### ✅ 第 10 课：鉴权中间件 + 权限

**关键认知**（`middleware/jwt_auth.go`）
- 401 = 不知道你是谁（跳登录）；403 = 知道你是谁但没权限（提示无权限）
- 校验失败必须 `c.Abort()`
- **整组挂中间件**而不是逐个加，避免「新增接口忘记鉴权」
- 身份信息只从 token 取，绝不信任前端传的 `author_id`
- 前端路由守卫只是体验优化，**真正的安全在后端**

**验收**
```bash
curl -X DELETE -H "Authorization: Bearer <author的token>" .../admin/articles/1   # 403
```

**做了什么**：`pkg/pagination` 提供 `Query.Normalize()` / `Offset()` / `NewResult()`，用匿名嵌入接入各列表接口。

### ✅ 第 12 课：分类 / 标签 / 归档

**关键认知**
- 分类下还有文章时**禁止删除**（保护引用完整性），返回 409 并说明原因
- 标签允许删，但必须**同时清理 `article_tags`**（事务内）
- 归档用 `DATE_FORMAT(published_at, '%Y-%m')` 分组
- 归档路径用 `/archives` 而非 `/articles/archives`，避免与 `:id` 冲突

### ✅ 第 13 课：评论（楼中楼 + 审核）

**关键认知**（`service/comment_service.go`）
- 树形结构用一维表 + `parent_id`，`0` 表示一级评论
- **组装树只查 1 次**：按 `parent_id` 分桶再挂载，不是递归查库（避免 N+1）
- 只支持两级：回复的回复直接拒绝
- 新评论默认待审核（`status=0`），前台不可见
- 删除父评论要**连带删回复**（事务），否则留孤儿
- IP 从 `c.ClientIP()` 取，不信请求体

### ✅ 第 14 课：评论防刷

**做了什么**：滑动窗口限流器（`internal/pkg/ratelimit`），同 IP 60 秒内最多 3 条。

**关键认知**
- **为什么用滑动窗口而不是固定窗口**：固定窗口在边界会放行 2 倍突发（00:59 打满 + 01:00 再打满）
- 限流判断放在参数校验**最前面**——刷接口的脚本连校验都不该跑
- 被拒绝时返回 **429 + 剩余秒数**，前端能直接提示「请 N 秒后再试」
- 记录时要顺手清理过期 key（`gcLocked`），否则大量不同 IP 会把内存撑爆
- **多实例部署时进程内限流不共享**，必须换 Redis（`INCR` + `EXPIRE`）

**验收**
```bash
# 连发 4 条，第 4 条应 429
for i in 1 2 3 4; do curl -s -o /dev/null -w "%{http_code} " -X POST \
  localhost:8090/api/v1/articles/1/comments -H "Content-Type: application/json" \
  -d "{\"nickname\":\"t\",\"content\":\"x$i\"}"; done; echo
# 200 200 200 429
```

### ✅ 第 15 课：图片上传

**关键认知**（`service/upload_service.go`）
- **类型判断看内容不看文件名**：`http.DetectContentType` 读前 512 字节
- **文件名由服务端随机生成**，彻底消除路径穿越
- 嗅探读走了 512 字节，必须 `Seek(0)` 回到开头，否则文件损坏
- 大小双限制：`MaxMultipartMemory`（内存）+ 业务 `maxMB`
- 按年月分目录，避免单目录文件过多

### ✅ 第 18 课：Markdown 渲染

**关键认知**（`frontend/src/utils/markdown.js`）

### ✅ 第 20 课：部署与收尾

**做了什么**：`deploy/nginx.conf`、`deploy/blog-server.service`、`deploy/build.sh`、`docs/03-部署.md`，以及 Element Plus 按需引入。

**关键认知**
- **生产必须配 `TRUSTED_PROXIES=127.0.0.1`**：Nginx 反代后，不配这个所有评论 IP 都是 127.0.0.1，限流会把全站用户当成同一个 IP
- Nginx 必须 `try_files $uri $uri/ /index.html`，否则刷新 `/article/1` 404

- systemd 用 `User=blog` 而非 root，`TimeoutStopSec` 要大于程序的排空超时
- 升级前先 `mysqldump` + 备份 uploads；二进制先传 `.new` 再 `mv`，避免覆盖运行中的文件
- **按需引入实测**：JS/CSS 1.7MB→1.0MB，最大 JS 830KB→141KB，最大 CSS 362KB→25KB（图片资源另计）

## 学习原则

1. **先跑通，再理解，最后优化** —— 每课都先让代码动起来
2. **报错不要猜** —— 把完整报错贴出来，看它到底说了什么
3. **验收要看证据** —— 不是「应该能跑」，而是「这条命令输出了这个」
4. **能写成测试的就写成测试** —— 安全相关代码尤其（hash / jwt 已有 12 个用例）
