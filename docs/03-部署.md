# 部署指南

> 目标：把本地跑通的项目部署到一台 Linux 服务器上，Nginx 对外、Go 服务在本机监听、systemd 托管。

---

## 一、部署形态

```
用户浏览器
    │  :80 / :443
    ▼
┌────────────────  Nginx  ────────────────┐
│  /            → /var/www/blog/dist      │  SPA 静态文件（try_files 回退 index.html）
│  /assets/     → 同上，长缓存            │
│  /api/        → 127.0.0.1:8090          │  反向代理到 Go
│  /uploads/    → 127.0.0.1:8090          │  图片
└───────────────────┬─────────────────────┘
                    │
          ┌─────────▼─────────┐
          │  blog-server :8090 │  systemd 托管，User=blog
          └─────────┬─────────┘
                    │
              ┌─────▼─────┐
              │  MySQL 8  │
              └───────────┘
```

**为什么这么分**：Nginx 负责静态文件（快、能扛并发、支持缓存和压缩），Go 只处理动态接口。让 Go 直接对外发静态文件是浪费。

## 二、服务器准备

```bash
# 1. 建专用用户（不要用 root 跑服务）
sudo useradd -r -m -s /bin/bash blog

# 2. 目录结构
sudo mkdir -p /opt/blog /var/www/blog
sudo chown -R blog:blog /opt/blog /var/www/blog

# 3. 装 MySQL、Nginx
sudo apt install -y mysql-server nginx

# 4. 建库与账号（同本地）
mysql -uroot -p <<'SQL'
CREATE DATABASE IF NOT EXISTS blog DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'blog'@'localhost' IDENTIFIED BY '换成强密码';
GRANT ALL PRIVILEGES ON blog.* TO 'blog'@'localhost';
FLUSH PRIVILEGES;
SQL
```

## 三、构建

**方式 A：本地构建后上传（推荐，服务器不用装 Go/Node）**

```bash
# 本机执行
./deploy/build.sh

# 上传
rsync -avz --delete backend/bin/blog-server   blog@server:/opt/blog/backend/bin/
rsync -avz frontend/dist/                     blog@server:/var/www/blog/dist/
rsync -avz backend/migrations/                blog@server:/opt/blog/backend/migrations/
```

**方式 B：服务器上构建**

```bash
# 需要 Go 1.24+ 和 Node 20+
cd /opt/blog && ./deploy/build.sh
```

> `go build -trimpath -ldflags "-s -w"` 已经在 Makefile 里配好：去掉调试信息和绝对路径，产物约 15MB 单文件，没有任何运行时依赖。

## 四、配置

```bash
sudo -u blog cp /opt/blog/backend/.env.example /opt/blog/backend/.env
sudo -u blog vim /opt/blog/backend/.env
```

**生产环境必须改这几项**

| 变量 | 改成 | 为什么 |
|---|---|---|
| `APP_ENV` | `prod` | 关掉 SQL 打印与 `/debug/*` 路由 |
| `DB_PASSWORD` | 强密码 | 别用 `blog123456` |
| `JWT_SECRET` | `openssl rand -hex 32` 的**新值** | 本地密钥泄露过就不能再用 |
| `TRUSTED_PROXIES` | `127.0.0.1` | **不配的话评论 IP 全是 127.0.0.1**，限流会把所有人当同一人 |
| `UPLOAD_DIR` | `/opt/blog/backend/uploads` 的绝对路径 | 相对路径依赖工作目录 |
| `COMMENT_RATE_LIMIT` | 按需，例如 `3` | 评论防刷 |

`.env` 权限设成 600：

```bash
sudo chown blog:blog /opt/blog/backend/.env && sudo chmod 600 /opt/blog/backend/.env
```

**执行数据库迁移**（只按顺序执行一次，执行过的文件不要改）

```bash
cd /opt/blog/backend
for f in migrations/00*.sql; do
  echo "==> $f"
  # --default-character-set=utf8mb4 不能省：服务器上 LANG 通常是空的，
  # mysql 客户端会默认用 latin1，中文被双重编码存进库后页面就是乱码。
  mysql -ublog -p --default-character-set=utf8mb4 blog < "$f"
done
```

## 五、启动

```bash
sudo cp deploy/nginx.conf /etc/nginx/conf.d/blog.conf
# 改里面的 server_name 和 root
sudo nginx -t && sudo systemctl reload nginx

sudo cp deploy/blog-server.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now blog-server

# 看状态与日志
systemctl status blog-server
journalctl -u blog-server -f
```

## 六、验收（上线前逐条过）

```bash
# 1. 服务活着
curl -s http://127.0.0.1:8090/api/v1/ping

# 2. 数据库连通
curl -s http://127.0.0.1:8090/api/v1/articles | head -c 200

# 3. debug 路由已关闭（prod 环境不应存在）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8090/api/v1/debug/db   # 期望 404

# 4. 后台接口未登录被拒
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8090/api/v1/admin/articles   # 期望 401

# 5. 图片上传后能访问
TOKEN=$(curl -s -X POST http://127.0.0.1:8090/api/v1/auth/login \
  -H "Content-Type: application/json" -d '{"username":"admin","password":"你的密码"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")
curl -s -X POST -H "Authorization: Bearer $TOKEN" -F "file=@/tmp/test.png" \
  http://127.0.0.1:8090/api/v1/admin/upload

# 6. 通过 Nginx 访问前端
curl -s -o /dev/null -w "%{http_code}\n" http://your-domain/
curl -s -o /dev/null -w "%{http_code}\n" http://your-domain/article/1    # SPA 回退是否生效

# 7. 真实 IP 是否透传（发一条评论，看数据库 ip 字段）
mysql -ublog -p blog -e "SELECT id,nickname,ip FROM comments ORDER BY id DESC LIMIT 1;"
# 如果显示 127.0.0.1 而不是你的公网 IP → TRUSTED_PROXIES 没配
```

## 七、生产安全检查清单

| 项 | 做法 | 验证方式 |
|---|---|---|
| 关闭调试接口 | `APP_ENV=prod` | `curl /api/v1/debug/db` 返回 404 |
| 更换 JWT 密钥 | 新生成，只放 `.env` | 旧 token 全部失效 |
| 数据库强密码 | 不用默认值 | — |
| `.env` 权限 600 | `chmod 600` | `ls -l .env` |
| 服务非 root | systemd `User=blog` | `ps -o user= -p $(pgrep blog-server)` |
| 上传类型白名单 | 已实现（按内容嗅探） | 传 `.php` 改名 `.png` 应 400 |
| 上传大小限制 | `UPLOAD_MAX_MB` + Nginx `client_max_body_size` | 传 10MB 图片应 400 |
| 评论限流 | `COMMENT_RATE_LIMIT` | 连发 4 条，第 4 条应 429 |
| CORS | 同域部署则不需要；跨域时白名单 | 当前实现回显 Origin，**跨域生产要收紧** |
| 软删除数据 | 定期归档或清理 `deleted_at` 非空的行 | — |
| 备份 | `mysqldump` + `uploads/` 一起备份 | 定期演练恢复 |
| HTTPS | certbot 申请证书，80 跳 443 | `curl -I https://域名` |

## 八、升级与回滚

**升级**

```bash
# 1. 备份
mysqldump -ublog -p blog | gzip > /backup/blog-$(date +%F).sql.gz
tar czf /backup/uploads-$(date +%F).tar.gz /opt/blog/backend/uploads

# 2. 上传新产物（二进制约 15MB，替换时先传临时名再 mv，避免运行中文件被截断）
rsync -avz backend/bin/blog-server blog@server:/opt/blog/backend/bin/blog-server.new
ssh blog@server 'mv /opt/blog/backend/bin/blog-server.new /opt/blog/backend/bin/blog-server && sudo systemctl restart blog-server'

# 3. 有新迁移就执行
mysql -ublog -p blog < migrations/00N_xxx.sql
```

**回滚**

```bash
# 二进制：保留上一版
ssh blog@server 'cp /opt/blog/backend/bin/blog-server.bak /opt/blog/backend/bin/blog-server && sudo systemctl restart blog-server'

# 前端：保留上一版 dist
ssh blog@server 'rm -rf /var/www/blog/dist && mv /var/www/blog/dist.bak /var/www/blog/dist'
```

> 迁移脚本**只加不改**，所以回滚代码通常不需要回滚表结构——这是当初定「迁移文件永久冻结」规则的回报。

## 九、性能优化记录（已做）

### 1. 前端按需引入 Element Plus

| 指标 | 优化前 | 优化后 |
|---|---|---|
| dist 总大小 | 1.7 MB | **1.0 MB** |
| 最大单个 JS | 830 KB | **141 KB** |
| 最大单个 CSS | 362 KB | **25 KB** |

做法：`unplugin-auto-import` + `unplugin-vue-components` + `ElementPlusResolver`，去掉 `app.use(ElementPlus)` 与全量 CSS；语言包改用 `<el-config-provider :locale="zhCn">` 下发。

### 2. highlight.js 按需注册

从 `import hljs from 'highlight.js'`（190+ 语言，约 1MB）改成 `highlight.js/lib/core` + 11 种语言，降到 143KB。

### 3. 后端连接池

```go
sqlDB.SetMaxOpenConns(50)      // 并发上限
sqlDB.SetMaxIdleConns(10)      // 常用连接常驻
sqlDB.SetConnMaxLifetime(30m)  // 定期回收，避免被中间件掐断的旧连接
```

调参依据：`/api/v1/debug/db` 返回的 `pool` 里看 `wait_count`（>0 说明连接不够）和 `open_connections`。

### 4. 索引

`articles` 上的 `(status, published_at)` 让「已发布 + 按时间倒序」的列表查询既不回表排序也不全表扫描。
验证：`EXPLAIN` 里 `Extra` **没有** `Using filesort`。

## 十、已知待优化

| 项 | 影响 | 建议 |
|---|---|---|
| 归档按月筛选用 `DATE_FORMAT` | `published_at` 部分索引失效 | 改成 `published_at >= ? AND published_at < ?` 范围查询 |
| 文章搜索用 `LIKE '%kw%'` | 无法走索引，数据量大就慢 | 全文索引 / Meilisearch |
| 分类、标签每次查库 | 小表无所谓，量大浪费 | 加 5 分钟内存缓存或 Redis |
| 限流数据在进程内存 | 多实例不共享 | 换 Redis `INCR + EXPIRE` |
| 上传存本地磁盘 | 多实例无法共享 | 换对象存储 + CDN |
| 无单测覆盖 service 层 | 重构时容易碰坏逻辑 | 引入 mock repository 或测试库 |
