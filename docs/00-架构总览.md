# 博客系统 · 架构总览

> 项目根目录：`/Users/taowenxin/Desktop/blog`
> 形态：前后端分离（Vue3 SPA + Go API）
> 目标：一套能跑、能讲、能改的博客系统，同时作为学习后端（Go / HTTP / MySQL / 分层 / 认证）的实操载体

---

## 1. 功能范围

### 前台（读者，无需登录）
- 首页：最新文章、置顶文章、分类导航
- 文章列表：分页、按分类/标签筛选、关键词搜索
- 文章详情：Markdown 渲染、阅读数、评论列表
- 归档页：按年月分组
- 标签页 / 分类页
- 关于页（站点介绍，静态可配）
- 游客评论（昵称 + 邮箱，可省略邮箱）

### 后台（作者/管理员，需登录）
- 登录 / 退出
- 文章管理：列表、新建、编辑、删除、草稿/发布、置顶
- 分类管理：增删改
- 标签管理：增删改
- 评论管理：审核通过 / 删除
- 个人资料：改昵称、头像、密码

### 本期不做（避免范围膨胀）
- 多作者协作与权限细分（只分 admin / author 两种角色）
- 富文本编辑器（用 Markdown 文本域 + 预览）
- 第三方登录、邮件通知、图片 CDN

## 2. 技术栈与选型理由

### 后端

| 项 | 选型 | 版本 | 为什么选它 |
|---|---|---|---|
| 语言 | Go | 1.26.4（本机已装） | 你要学的就是它；标准库 `net/http` 能讲清 HTTP 本质 |
| HTTP 框架 | Gin | v1.10.x | 上手快、中间件机制清晰、资料最多；学到第 2 课先从标准库 `net/http` 起步，再换 Gin，才知道框架帮你做了什么 |
| ORM | GORM | v2（gorm.io/gorm） | 能同时学「SQL 怎么写」和「ORM 怎么映射」，调试时可打印真实 SQL |
| 数据库 | MySQL | 8.4 LTS（Homebrew 安装） | 生产主流；能讲清索引、事务、字符集、隔离级别，SQLite 讲不透这些 |
| 认证 | JWT | golang-jwt/jwt/v5 | 前后端分离的标准做法；比 Session 更适合讲「无状态」 |
| 密码 | bcrypt | golang.org/x/crypto | 行业标准，顺手讲「为什么数据库不存明文」 |
| 配置 | .env + godotenv | - | 简单；顺便讲「配置不写死在代码里」 |
| 日志 | 标准库 log/slog | Go 1.21+ | 标准库够用，不引入 zap 增加认知负担 |
| 参数校验 | Gin binding（validator v10） | - | Gin 自带，`binding:"required"` 即可 |

### 前端

| 项 | 选型 | 为什么 |
|---|---|---|
| 框架 | Vue 3（Composition API + `<script setup>`） | 你选的方向 |
| 构建 | Vite | 秒级热更新 |
| 语言 | JavaScript（不启用 TS） | 按你的选择，降低学习成本 |
| 路由 | Vue Router 4 | 官方方案 |
| 状态 | Pinia | 官方推荐，比 Vuex 简单 |
| UI | Element Plus | 组件全（表格、表单、弹窗），后台管理省力 |
| 请求 | Axios | 拦截器统一处理 token 与错误 |
| Markdown | marked + highlight.js | 文章渲染与代码高亮 |

## 3. 整体架构

```
┌──────────────────────────────┐
│  浏览器  Vue3 SPA (:5173)     │
│  views / components / stores │
└──────────────┬───────────────┘
               │  HTTP + JSON
               │  开发期走 Vite dev proxy（/api → :8090，绕开跨域）
               ▼
┌──────────────────────────────────────────────┐
│            Gin 服务 (:8090)                   │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │ 中间件 Middleware                       │  │
│  │ CORS → 请求日志 → Recovery → JWT 鉴权   │  │
│  ├────────────────────────────────────────┤  │
│  │ Router  路由表（公开区 / 后台区）        │  │
│  ├────────────────────────────────────────┤  │
│  │ Handler 控制器                          │  │
│  │ 解析参数 → 校验 → 调 Service → 统一响应  │  │
│  ├────────────────────────────────────────┤  │
│  │ Service 业务层                          │  │
│  │ 业务规则、组合多个表、事务               │  │
│  ├────────────────────────────────────────┤  │
│  │ Repository 数据访问层                   │  │
│  │ 只负责 CRUD 查询，GORM 调用在这里         │  │
│  ├────────────────────────────────────────┤  │
│  │ Model 实体（GORM 结构体 + JSON tag）     │  │
│  └────────────────────────────────────────┘  │
└──────────────┬───────────────────────────────┘
               │ database/sql 连接池
               ▼
        ┌──────────────┐
        │ MySQL 8.4    │  blog 库
        └──────────────┘
```

**一次请求的完整链路（以「文章列表」为例）**

1. 前端 `GET /api/v1/articles?page=1&page_size=10&category_id=2`
2. Vite proxy 转发到 `http://127.0.0.1:8090`
3. 全局中间件：写访问日志、CORS 头、panic 恢复
4. 路由匹配到 `ArticleHandler.List`
5. Handler 把 query 参数绑定到 `ListArticleQuery` 结构体并校验
6. Handler 调 `ArticleService.List(query)`
7. Service 组装查询条件，调 `ArticleRepository.List(filter)`
8. Repository 用 GORM 拼 SQL：`SELECT ... LIMIT 10 OFFSET 0`
9. 结果逐层返回，Handler 用 `response.OK(c, data)` 输出 `{"code":0,...}`
10. 前端 Axios 拦截器收到 code=0 交给页面渲染

## 5. 分层依赖规则（写代码时的铁律）

```
handler ──► service ──► repository ──► gorm ──► MySQL
   │           │            │
   └── 共用 ──► model / pkg（只能单向依赖）
```

1. **只允许向下调用**：handler 不直接调 repository，service 不直接写 SQL。
2. **不允许反向依赖**：repository 不能 import service（否则循环依赖编译不过）。
3. **依赖注入**：`NewArticleHandler(svc *ArticleService)`，在 `main.go` 里一次性装配，不用全局变量。
4. **Handler 不写业务判断**：比如「文章不存在返回 404」由 service 返回 `ErrNotFound`，handler 翻译成 HTTP 状态码。
5. **Model 兼顾 GORM 与 JSON**：`PasswordHash string \`json:"-"\``，一行 tag 就防止密码泄漏。

这五条是「为什么后端要分层」的答案：**改一处不炸一片、能单测、能换实现**。第 7 课会专门讲。

## 7. API 规范

### 7.1 前缀与版本
统一 `/api/v1`，以后升级不破坏旧接口。

### 7.2 统一响应体
```json
{ "code": 0, "message": "ok", "data": {} }
```
- HTTP 状态码同时设置（200/400/401/403/404/500），便于网关和浏览器判断
- `code` 是业务码，前端只认 `code`

### 7.3 业务错误码

| code | HTTP | 含义 |
|---|---|---|
| 0 | 200 | 成功 |
| 10001 | 400 | 参数错误 |
| 10002 | 401 | 未登录 / token 无效或过期 |
| 10003 | 403 | 无权限 |
| 10004 | 404 | 资源不存在 |
| 10005 | 409 | 冲突（用户名/分类名已存在） |
| 10006 | 500 | 服务器内部错误 |

### 7.4 分页

请求：`?page=1&page_size=10&keyword=go&category_id=2&tag_id=3`
响应：
```json
{
  "code": 0,
  "message": "ok",
  "data": { "list": [], "total": 42, "page": 1, "page_size": 10 }
}
```
`page_size` 上限 100，默认 10。

### 7.5 路由表

**公开接口**
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/v1/articles | 文章列表（分页/筛选/搜索） |
| GET | /api/v1/articles/:id | 文章详情（阅读数 +1） |
| GET | /api/v1/articles/:id/comments | 评论列表（一级 + 子回复） |
| POST | /api/v1/articles/:id/comments | 发表评论 |
| GET | /api/v1/categories | 分类列表（含文章数） |
| GET | /api/v1/tags | 标签列表（含文章数） |
| GET | /api/v1/archives | 归档（年月 + 数量） |
| GET | /api/v1/site/info | 站点信息（关于页） |

### 7.6 认证方式
```
Authorization: Bearer <jwt>
```
token 载荷：`{ user_id, username, role, exp }`，有效期 24h，HS256 签名，密钥放 `.env`。

- 每个新概念第一次出现时，我在对话里讲清「是什么 / 为什么 / 不用它会怎样」
- 每课结束有验收命令，跑通了再进下一课
- 出错的报错原文直接发我，不自己猜
