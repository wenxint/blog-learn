## 2026-11-12 · mysql 命令导入 SQL 文件，中文全变乱码

**现象**

用 `mysql -ublog -p blog < migrations/002_seed.sql` 导入后，库里中文变成 `æŠ€æœ¯ç¬”è®°`（应为「技术笔记」）。

**根因**

- 文件本身是正确的 UTF-8（`E6 8A 80` = 技）
- 库里存的是双重编码（`C3A6 C5A0` = UTF-8 把 latin1 的解释结果又编了一次）
- 本机 `LANG` / `LC_ALL` 为空（`C` locale），**mysql 客户端按系统 locale 决定默认字符集，于是按 latin1 发送**
- 服务端声明 `character_set_client=utf8mb4` 但客户端实际发的是 latin1 字节，服务端按 latin1 解释 → 存进去就坏了

**解法**

客户端全局指定默认字符集，建 `~/.my.cnf`：

```ini
[client]
default-character-set=utf8mb4
```

或者每条命令都带 `--default-character-set=utf8mb4`。

**验证方法**

```sql
-- 存进去的字节应该是 E68A80...（技术）而不是 C3A6...
SELECT HEX(name) FROM categories WHERE id=1;
```

**顺带说清三层字符集**

| 层 | 参数 | 说明 |
|---|---|---|
| 服务端默认 | `character_set_server` | 建库时继承，我们用 utf8mb4 |
| 库/表 | `CHARSET=utf8mb4` | 数据实际存储编码 |
| **客户端连接** | `character_set_client` / `--default-character-set` | **最容易被忽略，就是这次的原因** |

三层必须一致，任何一层是 latin1 都可能乱码。

## 2026-11-12 · Homebrew 装 mysql@8.4 报 `unknown install step: init_data_dir`

**现象**

`brew install mysql@8.4` 输出 `Error: unknown install step: init_data_dir`，文件装上了但数据目录没初始化，服务起不来。

**根因**

本机 Homebrew 5.1.15 比 formula 旧，不认识 formula 里新加的 `init_data_dir` post-install 步骤。

**解法**

手动初始化数据目录：

```bash
mkdir -p /opt/homebrew/var/mysql
/opt/homebrew/opt/mysql@8.4/bin/mysqld --initialize-insecure \
  --datadir=/opt/homebrew/var/mysql --user=$(whoami)
brew services start mysql@8.4
```

`--initialize-insecure` 表示 root 初始无密码，随后用 `ALTER USER` 设密码。

## 2026-11-12 · 粘贴带 `#` 注释的命令报 `zsh: command not found: #`

**现象**

粘贴多行命令（含 `# 1. 确认结构` 这类注释行）时，zsh 报 `command not found: #`。

**根因**

zsh 交互模式默认**不识别** `#` 注释（bash 识别），需要显式开启。

**解法**

`~/.zshrc` 加一行：

```bash
setopt interactive_comments
```

## 2026-11-12 · git 里中文文件名显示成 `\346\236\266...`

**现象**

`git commit` 输出里 `docs/00-架构总览.md` 显示为 `"docs/00\346\236\266..."`。

**根因**

Git 默认 `core.quotepath=true`，会把非 ASCII 路径转义。

**解法**

```bash
git config --global core.quotepath false
```

## 2026-11-12 · 表建好了，但 migration 文件没保存

**现象**

`SHOW TABLES` 有四张表，但 `backend/migrations/` 目录是空的，Git 里也没有建表脚本。

**根因**

在 SQLTools（Cursor 数据库插件）的临时编辑器里直接执行 SQL，没有先保存成项目文件。那个临时文件（`blog-local.session.sql`）关掉就清空。

**解法 / 规矩**

1. **SQL 一律先写进 `backend/migrations/NNN_xxx.sql`，再执行**，执行方式二选一：
   - 终端：`mysql -ublog -p blog < migrations/001_init.sql`
   - SQLTools：打开该文件 → 点 ▶ Run
2. `*.session.sql` 已在 `.gitignore` 里，属于每台机器各自的临时文件，不进 Git
