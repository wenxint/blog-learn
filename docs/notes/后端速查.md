> 忘了怎么写的时候直接抄。

## 一、分层职责（写代码前先想清楚这段逻辑该放哪层）

| 层 | 目录 | 只做 | 绝不 |
|---|---|---|---|
| handler | `internal/handler/` | 解析参数、调 service、翻译错误、写响应 | 写 SQL、做业务判断 |
| service | `internal/service/` | 业务规则、校验、事务、状态流转 | import gin、拼 SQL 细节 |
| repository | `internal/repository/` | GORM 查询、数据存取 | 判断「草稿该不该展示」 |
| model | `internal/model/` | 表结构映射 | 写业务方法 |

依赖只能单向：`handler → service → repository → gorm`。反过来编译不过（这也是好处）。

## 二、新增一个接口的五个步骤

以「文章点赞」为例：

**① model**（表已存在就跳过）

```go
type ArticleLike struct {
    ID        uint64    `gorm:"primaryKey;autoIncrement" json:"id"`
    ArticleID uint64    `gorm:"index;not null" json:"article_id"`
    UserID    uint64    `gorm:"uniqueIndex:uk_article_user;not null" json:"user_id"`
    CreatedAt time.Time `json:"created_at"`
}
func (ArticleLike) TableName() string { return "article_likes" }
```

**② repository**

```go
func (r *ArticleRepository) Like(articleID, userID uint64) error {
    return r.db.Create(&model.ArticleLike{ArticleID: articleID, UserID: userID}).Error
}
```

**③ service**（业务规则在这层：不能重复点赞、文章必须存在）

```go
func (s *ArticleService) Like(id, userID uint64) error {
    if _, err := s.repo.FindByID(id); err != nil {
        return ErrNotFound
    }
    err := s.repo.Like(id, userID)
    if errors.Is(err, gorm.ErrDuplicatedKey) {
        return fmt.Errorf("%w: 你已经点过赞了", ErrConflict)
    }
    return err
}
```

**④ handler**

```go
func (h *ArticleHandler) Like(c *gin.Context) {
    id, ok := parseID(c)
    if !ok { return }

    if err := h.svc.Like(id, authctx.UserID(c)); err != nil {
        fail(c, err, "点赞失败")
        return
    }
    response.OK(c, gin.H{"liked": true})
}
```

**⑤ router 注册**

```go
api.POST("/articles/:id/like", middleware.AuthRequired(jwtMgr), articleHandler.Like)
```

## 三、事务模板（多表写入必用）

```go
err := s.db.Transaction(func(tx *gorm.DB) error {
    repo := s.repo.WithTx(tx)        // ❗ 必须用 tx 版的 repo

    if err := repo.CreateArticle(a); err != nil {
        return err                    // 返回 error = 自动 ROLLBACK
    }
    if err := repo.ReplaceTags(a.ID, tagIDs); err != nil {
        return err                    // 上面那条 INSERT 也会被回滚
    }
    return nil                        // 全成功 = COMMIT
})
```

**三个常见错误**
1. 事务里混用 `s.db`（跑到事务外面了）
2. 忽略 `Transaction` 返回的 error
3. 事务里做远程调用 / 长耗时操作（长事务锁表）

## 四、分页模板

```go
type ListQuery struct {
    pagination.Query
    Keyword string `form:"keyword" binding:"omitempty,max=50"`
}

func (h *XxxHandler) List(c *gin.Context) {
    var q ListQuery
    if err := c.ShouldBindQuery(&q); err != nil {
        response.InvalidParam(c, "参数错误: "+err.Error())
        return
    }
    q.Normalize()                   // 默认 20、上限 100

    list, total, err := h.svc.List(...)
    if err != nil { fail(c, err, "查询失败"); return }

    response.OK(c, pagination.NewResult(list, total, q.Query))
}
```

## 五、错误处理模板

```go
// service：用哨兵错误表达「业务上出了什么事」
return fmt.Errorf("%w: 标题不能为空", ErrInvalidInput)

// handler：统一翻译（写一次，全项目共用 handler/errors.go 里的 fail）
fail(c, err, "创建文章失败")
```

| service 错误 | HTTP | 业务码 | 前端表现 |
|---|---|---|---|
| `ErrInvalidInput` | 400 | 10001 | 提示具体哪里错 |
| `ErrUnauthorized` | 401 | 10002 | 跳登录 |
| `ErrForbidden` | 403 | 10003 | 提示无权限 |
| `ErrNotFound` | 404 | 10004 | 提示不存在 |
| `ErrConflict` | 409 | 10005 | 提示冲突原因 |
| 其他（未包装） | 500 | 10006 | 只显示「服务器错误」，细节进日志 |

## 六、中间件顺序（改之前先想清楚）

```go
r.Use(
    middleware.RequestID(),   // 最外层：内层要靠它塞进 Context 的 ID 打日志
    middleware.Logger(),      // 在 c.Next() 之后打印，才能拿到最终状态码
    middleware.Recovery(),    // 兜 panic，必须包住业务
    middleware.CORS(),        // 预检请求直接 Abort，不进业务
)
```

**规律：越靠外，保护的代码越多；越靠内，越靠近业务。**

## 七、GORM 水坑清单

| 坑 | 症状 | 解法 |
|---|---|---|
| 链式对象复用 | 条件叠加、查询结果奇怪 | 用函数每次返回 `r.db.Model(...)` 新对象 |
| `Save` 带关联 | 连带把 users/categories upsert 一遍 | `Omit(clause.Associations).Save(a)` |
| `Association.Replace` | 顺带 upsert 关联表 | 手写中间表 delete + insert |
| 预加载没做 | 列表 20 条发 21 条 SQL | `Preload("Category")` |
| NULL 扫描失败 | `converting NULL to time.Time` | 字段用 `*time.Time` |
| 软删除没生效 | 删了还能查到 | 确认模型里有 `gorm.DeletedAt` |
| 并发更新丢数据 | 阅读数越点越少 | `gorm.Expr("view_count + 1")` |
| 唯一键冲突没提示 | 500 而不是 409 | 判断 `gorm.ErrDuplicatedKey` |

## 八、鉴权速查

```go
// 1. 整组挂鉴权
admin := api.Group("/admin")
admin.Use(middleware.AuthRequired(jwtMgr))

// 2. 单个路由额外要求 admin 角色
admin.DELETE("/articles/:id", middleware.AdminOnly(), articleHandler.Delete)

// 3. handler 里取当前用户（只能来自 token）
userID := authctx.UserID(c)
role := authctx.Role(c)
```

**绝不要** `req.AuthorID` 直接用前端传的值。
