# 前端视觉重构：Terminal Editorial

> 2026-11-14。把原来「圆角卡片 + 浅灰阴影」的模板化界面，重做成一套有明确主张的视觉语言，并做全站移动端适配。
>
> 设计方法论来源：
> - [anthropics/skills → frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design)（Anthropic 官方，Apache-2.0）
> - [vercel-labs/agent-skills → web-design-guidelines](https://github.com/vercel-labs/agent-skills)（安装量最高的前端设计 skill）

## 一、为什么原来的样子显得「丑」

不是配色问题，是**信息层次缺失**。原来的界面命中了官方 skill 里点名的两种「AI 生成页默认审美」：

1. **SaaS-card kit**：所有内容切成同样的圆角卡片，同一个 `border-radius`，同一档 `rgba(0,0,0,.1)` 阴影，再用渐变洗底做装饰。卡片之间没有主次，读者视线无处停留。
2. **模板化饰件**：用中点 `·` 拼接元数据、全大写标签、每个区块都 fade-in、每张卡片都 hover 抬升——这些是「不管什么主题都长这样」的默认值，而不是为这个博客做的选择。

## 二、设计计划（先 token，后代码）

### 概念

**一份深夜写就的工程手记。**

深墨蓝的纸面、琥珀色的批注、等宽字体的标题像终端里的命令；正文换成衬线字，保证三千字的技术文能读下去。

### Color

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#0B0F16` | 深墨蓝黑。**不是纯黑**，避开「黑客风」俗套 |
| `--panel` | `#111826` | 面板块（终端窗、输入框底） |
| `--ink` | `#E7ECF5` | 主文字 |
| `--ink-2` | `#98A5BB` | 次要文字 |
| `--ink-3` | `#5C6980` | 弱化信息 |
| `--amber` | `#F5B942` | **唯一点缀色**：链接、当前项、主张关键词 |

刻意避开：纯黑 + 荧光绿的「黑客套件」；奶油色 `#F4F1EA` + 陶土色 `#D97757` + 高对比衬线。

### Type

两个字族，各司其职：

| 角色 | 字体栈 | 为什么 |
|---|---|---|
| 标题 / 元数据 / 日期 / 序号 | `JetBrains Mono → SF Mono → Menlo` | 等宽字自带「终端 / 代码」语义，和博客主题同源 |
| 正文 | `Source Serif 4 → Songti SC → Georgia` | 长文阅读需要衬线，正文行高 1.9 |
| UI 文案（按钮/表单） | 系统无衬线（苹方 / 微软雅黑） | 控件里用衬线会显得做作 |

字号用 `clamp()` 平滑过渡，不用一堆断点硬切。

### Layout

- 内容上限 `72rem`，**正文行宽收在 `42rem`（约 68 字符，符合 < 80 字符的排版规范）**
- 首页：左侧主张 + 右侧一枚终端窗口，**不对称**
- 列表：行式清单，左侧大号日期作为**真实的时间序列索引**（不是装饰性 01/02/03）
- 内容页：不用卡片，用细线分隔段落

### 唯一「大胆」的地方

按 skill 的建议——**只在一处大胆，其余克制**：

> 只有首页 hero 是视觉焦点（大标题 + 终端窗口 + 入场编排）。
> 其余页面（详情、归档、标签、关于、后台）全部是安静的文字排版。

动效也只编排一次：hero 的三段依次浮现（`rise` 0.7s，延迟 0/0.12/0.24s），**不做逐区块 fade-in，不做每卡片 hover 抬升**。

## 三、移动端：rem 适配方案

全站尺寸统一用 `rem`，通过 `html` 的基准字号整体降档，所有尺寸等比缩放：

```css
html { font-size: 16px; }              /* 桌面基准 */
@media (max-width: 48rem)  { html { font-size: 15px; } }   /* 768px 以下 */
@media (max-width: 30rem)  { html { font-size: 14.5px; } } /* 480px 以下 */
```

媒体查询断点本身也用 `rem`（`48rem` = 768px，`30rem` = 480px），保持一致。

实测（390×844 视口）：

```
scrollWidth = 390   innerWidth = 390   → 无横向溢出
rootFontSize = 14.5px                  → rem 降档生效
```

### 各页面的窄屏策略

| 页面 | 窄屏处理 |
|---|---|
| 头部导航 | 收成整屏覆盖菜单，汉堡按钮两条线交叉成 ×，路由切换自动收起 |
| 首页 hero | 单列；终端窗口直接隐藏（手机上没有空间让它有意义） |
| 文章列表 | 日期从独立一列改为行内小字 |
| 文章详情 | 宽表格改横向滚动；正文 1rem / 行高 1.85 |
| 评论表单 | 两列改单列 |
| 归档 / 标签 / 关于 | 字号与留白降档，技术栈卡片两列→单列 |
| 后台侧栏 | 变成顶部横向可滚动菜单 |
| 后台表格 | 设 `min-width: 42rem`，让 Element Plus 内部横向滚动，避免列压缩重叠 |

## 四、质量底线

做完不算完，这些都验证过：

| 项 | 状态 |
|---|---|
| 键盘焦点可见 | `:focus-visible { outline: 2px solid var(--amber) }` |
| 尊重减少动效 | `@media (prefers-reduced-motion: reduce)` 全局降级 |
| 无横向溢出 | 6 个页面在 390px 下 `scrollWidth == innerWidth` |
| 对比度 | 主按钮改为「琥珀底 + 深色字」（白字在琥珀上只有 2.4:1，不达标） |
| 语义 | 装饰性终端窗口 `aria-hidden="true"`，汉堡按钮有 `aria-expanded` 和 `aria-label` |

## 五、实现要点（踩过的细节）

### 1. CSS 压缩会把媒体查询改写成语义不同的语法

默认构建目标下，esbuild 会把 `@media (max-width: 768px)` 压成 **Media Queries Level 4** 的 `@media (width<=768px)`。这个语法旧版 Safari（<16.4）和旧 Android WebView 不认——**媒体查询整个失效，移动端样式全崩**。

解决（[vite.config.js](../frontend/vite.config.js)）：

```js
build: {
  cssTarget: ['chrome87', 'safari13', 'firefox78', 'edge88'],
}
```

### 2. Element Plus 主色覆盖失效

`main.css` 里覆盖了 `--el-color-primary`，但按钮还是亮蓝。原因是 **CSS 引入顺序**：Element Plus 的暗色变量在 `main.css` 之后引入，把覆盖盖掉了。

解决（[main.js](../frontend/src/main.js)）：先引入 `element-plus/theme-chalk/dark/css-vars.css`，**再**引入 `main.css`。

### 3. 导航高亮在子路由下全亮

`router-link-active` 对 `/` 是前缀匹配，导致 `/archive` 下「首页」和「归档」同时高亮。

解决：改用 `router-link-exact-active`。

### 4. 响应式表格被压到列重叠

移动端表格按容器宽度硬挤，标题列和操作列会叠在一起。

解决：`min-width: 42rem` 触发 Element Plus 内部的横向滚动。

用 Chrome headless + `puppeteer-core` 在真实视口下截图与断言，而不是只靠肉眼看代码：

- 桌面 1280×800 / 移动 390×844（`deviceScaleFactor: 2`, `isMobile: true`, `hasTouch: true`）
- 遍历 `/`、`/article/1`、`/archive`、`/tags`、`/about`、`/admin/login`
- 断言 `documentElement.scrollWidth <= innerWidth`（无横向溢出）
- 读取计算样式验证颜色、字号、`rootFontSize`
- 登录后验证后台表格与按钮
